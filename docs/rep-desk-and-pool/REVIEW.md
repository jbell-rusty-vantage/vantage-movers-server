## Findings and resolution

1. **Known attached money lost through same-job unlinked aliases (resolved and tested).** The first draft treated an unlinked Lead sharing `normalized_job_no` as a conflicting monetary identity and suppressed the reciprocal linked Booking's known dollars. The revised gate builds ambiguity only from reciprocal attached Booking anchors; an unlinked same-job alias no longer erases established money. The focused money test proves a reciprocal linked Form Lead retains its amount beside an unlinked same-job Call Lead.
2. **Daily call goals empty-state column span (resolved in code).** The Team goals table has six headers/cells; its loading/error/empty rows were inadvertently changed to `colSpan=7` when the separate Attention table gained a Move date column. Goals now retains six; Attention retains seven.
3. **Mock browser money read missing (resolved in code).** The local desk mock had no `rep-metrics` handler. A role-scoped synthetic handler now serves the money DTO; foreign Rep ids are refused. The focused presentation test validates the handler, move-date filters/URL round trips, null-last mock paging and shared live invalidation.
4. **Cancellation linkage without mirrors (resolved in code).** Normal cancellation writers mirror to Booking and Lead in the same transaction, while existing received-Lead reporting also recognizes independent canonical Cancellation linkage. The metrics loader now overlays cancellation ids from `CancelledLead` by either canonical Lead or attached Booking anchor; a focused test proves exclusion when both mirrors are absent.
5. **Partial identity lost before official leadless eligibility (resolved and tested).** A legacy leadless Booking with only `lead_ref` or `lead_model` retained was mapped to a null canonical Lead; passing neither raw identity field to `isGranotOfficialLeadlessBooking` could incorrectly admit the record. The internal money adapter now preserves both raw identity fields and supplies them to the existing helper. Six partial/unsupported/null-pointer combinations fail the gate; valid absent/null leadless and linked Call Bookings still count. Independent focused money file execution passed; the backend lane reports all 9 money checks and scoped lint passed. No DTO or lifecycle policy changed.
6. **Proof helpers reused a fixed entity revision (resolved and verified on the indexed replica).** Both local helper scripts initially emitted repeated `1 → 2` changes for one Booking. The declared unique `(entity.model, entity.id, revision_after)` index would reject a subsequent proof mutation or restoration. Read-only inspection confirmed the original proof database's `entity_changes` collection had only `_id_`, explaining its successful prior runs. The shared synthetic seam now commits a revision CAS on the aggregate and a schema-validated immutable receipt in one transaction; it recomputes from the current aggregate when the transaction retries and skips unchanged values. Mutations require loopback, a resolved test database and a `PHASE1-` aggregate Job Number. The explicit legacy cleanup also requires the exact disposable `testvantagemovers_phase1` database and matches only the two original synthetic proof command names. All declared EntityChange indexes were installed and asserted, including the unique revision index. Four browser-helper mutation/restore cycles advanced revisions `3 → 4 → 5 → 6 → 7`; repeated restore made no write. The real live proof and all three actual browser acceptance tests then passed with this index enabled. See [`phase1-local-integration.md`](phase1-local-integration.md) for reproduction and evidence.
7. **Ticking presentation time affected snapshot consumers (resolved and tested).** The interpolated clock was passed to queue date filters and existing cadence/age/status display helpers as well as the new relative labels. This does not fabricate verified overdue status (which still requires the server status), but can mix calendar windows with older money/goal snapshots at midnight. My and Team now retain snapshot time for filters and existing cadence/age/status presentation, and pass separate `relativeNow` only to move-date/interaction labels. The two rendered midnight regression checks pass: relative labels advance while Lead age, scheduled SMS day and proved overdue duration remain at the snapshot. The admin lane's focused snapshot/presentation/render test files passed; independent diff review confirms both call sites use the queue snapshot where applicable.

Independent focused commands passed: `node --import tsx --test src/services/salesOutreach/reads/repMetrics.test.ts` in server and `node --import tsx --test tests/outreach-desk/rep-presentation.test.ts` in admin. Direct file executions also passed all 8 money checks, all 6 presentation checks and all 3 live-hint checks in `src/services/salesOutreach/live/repMetrics.test.ts`. These establish pure money/coverage/permissions/date, hint role isolation and presentation/mock/URL/clock behavior; they do not by themselves establish deployed or actual browser behavior.
