## Exact imports and data flow

All implementation paths below are server-relative under `src/services/salesIntelligence/`.

1. `analysis/worker.ts:runIntelligenceJob(jobId?,stage?,deps?)` claims existing `analysis`/`number_refresh` jobs. CSI-12 `[conversation_id,transcript_snapshot_id]` is unchanged. `analysis/sources.ts:conversationAnalysisInput` checks current eligibility, version and media digest before paid work without retranscription.
2. Existing `analysis/run.ts:prepareIntelligenceRun(lease,input)` freezes prompt/model/subject. Existing `recoverIntelligenceSubmission(runId,lease)` precedes any repeat provider work, including reclaimed jobs with expired credentials.
3. `analysis/runtime.ts:invokeIntelligenceAgent(InvocationInput)` retrieves MCP prompt/resource and preflights captured context/activity/official records/identities/transcripts. `InvocationStep={step,usage,actual_cents,schema_failures}` persists input/output/reasoning usage. The SDK remote tools forward only to MCP. A receipt stops the loop; prose cannot complete a run.
4. CSI-17 intake creates application `[run_id,submission_id]` paused `invocation_pending`, or `consumer_unavailable` when disabled. Orchestration marks `invocation_complete` and releases its compatible intent. `analysis/readiness.ts:resumeApplicationIntents` validates stored bindings and preserves other pause reasons.
5. `analysis/apply.ts:runIntelligenceApplicationJob` verifies immutable envelope/manifest and uses `jobs.ts:checkpointCsiJob(lease,mutation)` for five-finding batches. Cursor and effects commit together. CSI-06 `applyOutreachEffect` resolves live authority/Owner/history rules; `ensureNumberReview` handles eligible number-only commitments. No Lead is invented. Each effect has a persisted outcome; exact quotation/entailment stays `not_run`.
6. The final transaction publishes existing conversation summary/current-run or number running-summary fields, run counts/status and completes the job. Newer current runs and replaced transcripts win. Number synthesis reads original transcript pages and findings through MCP, and does not duplicate conversation effect application.
7. `analysis/scheduling.ts:scheduleNumberIntelligence(numberId,session)` coalesces existing refresh signals. `scanIntelligenceChanges()` reuses existing SyncState/lease storage with five-number keyset batches. Source fingerprint includes calls/transcripts, reviewed identity, attachment, official state, followups, restrictions and Owner instructions. Generic updatedAt and clock-only changes are excluded. Oversize source sets remain visible as paused incomplete coverage.

`worker.ts:recoverExhaustedIntelligenceReceipts()` re-admits only a final crashed claim with a proven submitted receipt; the same worker then recovers without another provider call. `coverage.ts:capturedTranscriptsComplete()` verifies pagination coverage for legacy/application receipts without adding quote/entailment validation. `outreach/effects.ts:applyUnboundContactTypeEffect()` handles contact evidence before Outreach creation using the same contact-type decision and `ensureInteraction`; `review/restrictions.ts:applySpokenRestriction()` handles number-only restrictions. Owner edits win. Unresolved temporary restriction dates are review rather than indefinite restrictions. Publication also compares sources to schedule at most one successor; semantically unchanged findings do not refresh solely because their run/snapshot IDs changed.

The coordinated CSI-06 matcher retains existing obligations when speaker certainty changes, adds source finding provenance, honors a captured explicit target, and reviews conflicting/uncertain matches instead of creating duplicates. Number synthesis remains in flight until its application boundary, preventing a series of new model jobs while publication is pending. Run states reflect budget/disabled pauses and terminal eligibility exclusion; unreported reasoning detail is nullable rather than fabricated zero.
