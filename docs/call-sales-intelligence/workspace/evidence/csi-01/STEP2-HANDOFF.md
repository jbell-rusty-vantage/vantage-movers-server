## Authentication and transaction boundaries

Owner requests pass the existing v1 guard and signed Registry Owner verifier; unsigned broad-secret access is denied. Agent requests need the named dedicated scoped principal plus a signed run token bound to run, subject, tool set, audience, deployment/database, nonce, expiry and current job lease epoch. Hard routing bounds the service principal even if an operator gives its configured key an overly broad route. TEST_MODE model routing uses the isolated database, never the production model cache. Runtime token issuance loads the stored run and leased job; it does not trust client claims.

The command executor establishes trusted Owner scope, hashes command/payload, replays a stored identical result and rejects changed-payload reuse. Its callback must validate business preconditions and pass the supplied session to all mutation, audit and enqueue operations. Mongo rolls the whole callback back on failure. No external call belongs inside a retried transaction. Job completion similarly fences the current lease after the effect callback before commit; expired workers cannot retain callback effects.
