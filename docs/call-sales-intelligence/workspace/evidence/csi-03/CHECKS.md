## Replica environment

Same disposable Docker MongoDB 8.0 single-node replica as CSI-02 (`csi01`, loopback 27189; recipe in [csi-02/CHECKS.md](../csi-02/CHECKS.md)). The runner `scripts/test-csi-fanout.ts` refuses any other host, ignores `.env`, sets `SALES_INTELLIGENCE_CAPTURE_WEBHOOK=true`, `RINGCENTRAL_WEBHOOK_ENABLED=false` (toggled inside tests) and `CRON_SECRET`, and selects a fresh `testvantagemovers_csi03<random>` database that the test drops in its `finally`. No production database, provider, queue, subscription or messaging action occurred; the queue publisher is gated off in test runners.

## What the database proofs cover

Route acknowledges 200 with the receipt and the deduplicated `capture_projection` job durable (job `input_refs` = receipt `_id`, dedupe key from the provider uuid); duplicate uuid → one receipt, one job, `existing`; flag matrix (capture off → receipt only, no CSI job; capture on with `RINGCENTRAL_WEBHOOK_ENABLED=true` → candidate evaluation still runs and the job is created; qualified cursor collection never written); receipt without uuid keyed by `_id`; validation handshake body → receipt stored, no job from route or recovery; enqueue failure (dataset identity unset) → 200 `enqueue_failed`, receipt durable, no job → watermark recovery creates exactly the missing jobs once (including a receipt stored while the flag was off), second scan creates none, watermark written under the fenced lease, two concurrent recoveries elect one holder; recovery paging: clustered-overlap stream with batch 3/maxPages 2 keeps the watermark monotone and resumes after the keyset position, quarantines a deterministic conflict, completes with a larger budget, and a 10-receipt same-millisecond cluster pages 3+3+3+1 with each receipt ensured once; worker completes a job with `actor.request_id` = job id on interaction audit rows, `job`-kind `capture_projection.completed` audit row, `job.result`, and replay on the completed job is `not_claimable`; per-session `account_unresolved` completes with the code visible in result and audit and no fabricated row; retryable `persist_failed` → `retry` with partial result, later recovered by the same handler; two workers on one job → one `completed`, one `not_claimable`; expired lease holder cannot `completeCsiJob` or `failCsiJob` after a successor (epoch +1); queue consumer dispatches the same handler, `outreach_ensure` wake-up → `no_consumer` with the job untouched; unknown job / payload with `stage` rejected; cron job-recovery drains the rest under `CRON_SECRET`, flag-off crons return `skipped: disabled`.

## What is not proven here

Live RingCentral webhook delivery, validation handshake against a real subscription, subscription create/renew/repair on the real account (the ops command's mutating actions were never run), Vercel Queue delivery and consumer invocation (publisher is gated off outside a Vercel runtime; the trigger is asserted by reading `vercel.json`), production cron invocation, multi-node replica failover, downstream consumers for `outreach_ensure`/`attachment_refresh`/`recording_discovery` (Team C / CSI-11).
