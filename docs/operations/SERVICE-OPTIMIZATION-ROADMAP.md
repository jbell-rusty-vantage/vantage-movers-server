## How a service advances

The Owner separated implementation and immediate tests, longer isolated qualification runs, and scheduled production observation on November 18. The active engineering task owns the code and finite test runs. The twice-daily Codex **Vantage production watch** collects natural production evidence at 08:15 and 21:15 New York time. A dated observation gates the live claim it measures while other engineering proceeds. [Current assignments](NEXT-SESSION.md#implementation-and-testing)

Each service gets one bounded pass through the same gates:

| Gate | Evidence required |
| --- | --- |
| A — understand and measure | Entry points, owning collections, producer/consumer links, effects, replay/lease/transaction identities and recovery path; bounded cost baseline with query/command counts, bytes and workload shape. Unknown live data is explicitly unknown. |
| B — implement | A selected improvement reduces measured work without changing protected business behavior. Reuse existing implementations. If no safe gain is justified, record the measured reason and next prerequisite; do not manufacture a refactor. |
| C — qualify locally | Focused behavior/recovery tests, real replica proof where durable behavior matters, before/after measurement, relevant regression, typecheck/lint and independent review. Every skipped proof is recorded. |
| D — make operable | Supported inspect/trace/test commands, useful failure codes and evidence limits, executable runbook, and an unfamiliar agent's seeded-failure rehearsal. Repairs reuse canonical commands and existing owner controls; a service need not gain a new CLI repair command. |
| E — release | Exact reviewed source, compatible rollback, required build checks, explicit release authority, deployment identity and actual enabled configuration. Commit, deployment and activation are separate facts. |
| F — qualify in production | Naturally occurring representative work preserves outcomes and recovery; arrival/drain/latency and work-per-operation support the claimed gain. Record the actual observation window, workload and limits. No synthetic customer effects to close a gate. |

**Engineering-ready** means A–D are closed for the declared slice. **Production-qualified** requires E–F too. A phase is not simply “done” because code or tests exist. An explicit deferral names the missing proof/decision and preserves it in the ledger.

Use one active service implementation lane. Parallel agents may measure, implement separate files, review and rehearse that service; keep integration with one coordinator. Once A–D close, the next service may begin while the prior service waits on owner release or a real observation window. Keep that release obligation visible; never waive it or bundle unrelated changes to hide it.
