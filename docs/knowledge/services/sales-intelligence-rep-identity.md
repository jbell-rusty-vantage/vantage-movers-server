# Rep Identity Links — CSI-10

GET never runs the matcher: directory proposal results (including ambiguous/unmatched Users) are read from the existing durable `propose_reps` command responses for the current snapshot. Users with no stored proposal evidence are `not_proposed`. POST is the only proposal-generation path. No parallel proposal collection is needed.

Runtime: `src/services/salesIntelligence/repIdentity/`. Authority: [specification](../../call-sales-intelligence/01-specification.md), [contracts](../../call-sales-intelligence/workspace/CONTRACTS.md), [handoff](../../call-sales-intelligence/workspace/evidence/csi-10/HANDOFF.md).

Proposals consume stored account-scoped directory snapshots and canonical Agent `name`/`name_aliases`. Only User extensions qualify. Exact names, aliases and first tokens are evidence; no match implies review. All matching candidates remain visible, including weaker matches beside an exact one. Ambiguous/unmatched Users are read DTO evidence rather than invented Agent references. Proposal pages create only unique-candidate proposed links and never update any existing extension history. The historical September roster is not imported as authority. Missing snapshots, inconsistent counts/duplicate ids, and unverified provider completeness are explicit. No provider refresh occurs.

Owner routes are GET/POST `/reps`, GET `/reps/:id`, POST `/reps/propose`, POST `/reps/:id/review` under the existing CSI prefix. Writes use signed Owner authentication, strict schemas, expected revisions, durable payload-sensitive command replay, transactions, and append-only CSI audit. Create remains proposed. Review validates the current stored User directory and canonical active Agent. Agent's current username comes from `granot_identity.username`, falling back to `granot_crm_username`; no Agent or Extension User writes occur. This CSI-10 service does not send messages. CSI-14 consumes reviewed channel metadata as necessary configuration alongside current identity, explicit Owner authorization, policy, feature, destination and rate-limit checks; metadata alone is not a send grant.

Temporal intervals are half-open `[effective_from,effective_to)`. `resolveRepIdentities` is the account/extension/event-time authority. Proposed links never resolve; reviewed retired links resolve before their end, while unreviewed retired proposals never do. Conflicting applicable authority fails closed. Non-sales roles cannot establish Sales Rep authority. Existing legacy `reviewed` rows retain status authority; retiring them pins the review metadata. One Agent can have several extensions. The unchanged current unique index plus a transactional per-account/extension SyncState write fence protect concurrent commands, including finite historical overlap checks. Reviewed edits create successor intervals and retire the predecessor atomically; predecessor Agent/role/channels remain historical. A successor must start after the predecessor's start, within its existing interval. In-place rewrites of reviewed history are intentionally rejected; Owner decisions remain audited.

Review/retirement commits a `rep_identity_reevaluate` job with a fixed event window ending at command time. The worker processes 25 canonical interactions per transaction in `(started_at,_id)` order and creates its continuation atomically. The drain stops after five pages or 20 seconds. A durable typed window lives on the existing CSI job, with unchanged ObjectId `input_refs`, payload hashing and lease fencing. Queue dispatch and the existing minute recovery cron reach this stage under ENABLED. It schedules existing Outreach and recording-discovery jobs even when those consumers' flags are off; those flags govern execution. No provider work is performed here. Deferred stored-media rows become due for CSI-12's existing bounded scheduler; media/transcription eligibility retries retain their existing retry policies.

CSI-06's applied-call fingerprint includes resolved identity evidence, so unchanged call revisions can be re-evaluated. Actual attempt/human evidence remains separate. Owner assignment and explicit Owner unassignment survive; established owners are never casually replaced. Unknown promises stay unassigned. Identity-only replay may fulfill still-open obligations using existing call rules, but never recreates a previously applied missed-call episode. Official/Owner closure and cancelled obligations remain terminal. CSI-11/12 eligibility uses the same temporal resolver. Future CSI-13 must include its fingerprint in meaningful-change checks; future CSI-14 must check current reviewed identity and its own explicit send authorization.

Reads never write or enqueue. Link metrics are unknown/null because this issue does not implement rep metrics. Links and directory Users have independent bounded cursors. No new index or production migration is required; existing foundation unique indexes are mandatory and checked by models. Additive job metadata is nullable for old jobs. Rollback keeps ENABLED off for identity commands/recovery and leaves history/jobs intact; stage flags continue to protect downstream effects. No new environment keys are required, and all existing flags remain off by default.
