## Open

- `effectiveBookingSourceCompany` JSDoc says prefer label lookup then parse. The body casts `trim()` as `SourceCompany`, or `String(lead.source_company ?? "not_provided")`. Both from-source call sites pass `undefined`. The real display-source → company map is `getFormLeadSourceCompanyForBooking` → `resolveSourceCompany` (config aliases, not Registry). Finder writes (phone/Job overwrite, unmatched `create`) commit with no session before Book This Lead. Do not silently merge. See `recommendations/bookings-booking-source-resolver.md`.
- `docs/knowledge/services/bookings.md` Lead mirror says `mirrorBookingToLead` “recomputes CPL unless `preserveExistingCpl=true` (reconciliation / employee claim paths).” The condition is `sourceCompany || !preserveExistingCpl` — a Source Company plus preserve still reprices. Employee submit claims only (never mirrors, so never reprices). Employee attach claims, then mirrors with `preserveExistingCpl: true` and no `sourceCompany`. Do not silently merge. See `recommendations/bookings-booking-mirror.md`.
- `docs/knowledge/services/bookings.md` Leadless says a `BookingLeadReconciliationCase` opens only when `ingestion_source=best_relocation_sheet`. `createLeadlessBooking` (leftover public) honors that body flag. `runExistingCreateLeadlessBooking` stamps the flag from `provenance.origin === "external_sheet_ingestion"` and drops the body value. `POST /api/v1/leadless-bookings` always builds `vantage_admin` provenance, so a body flag on that route never opens a case. Knowledge’s HTTP table still names leftover `createLeadlessBooking`. Do not silently merge. See `recommendations/bookings-leadless-booking.md`.

See `recommendations/bookings-booked-lead-from-source.md`.

Do not silently merge. See `recommendations/leads-call-lead-source-match.md` and `recommendations/leads-lead-source-compatibility.md`.
